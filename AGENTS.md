# Architecture rules

- The six-step journey retains legacy stored progress IDs (final step 9, finished room 10) and maps them for display; removed-step URLs continue to the final step so existing accounts and bookmarks remain usable.

- Layout generation appends options to current state and ignores results after leaving the screen; late plan readers must not clear displayed layouts, so selection and edits survive background work.

- Project SELECT policies must check row ownership directly before membership helpers so INSERT RETURNING can read newly created owner rows within the same statement snapshot.

- Keep furniture groupings, plan symbols, side clearances, and wall-gap rules in database reference tables; publish only active groupings and preserve customized reference values when seeding defaults.

- Assemble generation moodboard references with the shared moodboard context helper, preserving role labels; attach images in priority order up to a memory-safe cap and name any remaining references in prompt text, because too many inline images exceed edge worker memory.
- Prefix non-surgical generation prompts with the shared moodboard brief independently of editable prompt templates; this keeps user selections authoritative even when templates omit placeholders.- Translate UI by English source text: `src/i18n` applies the `ar.json` dictionary to rendered text and attributes and sets `dir`, and adds `uiLanguage` to function calls. Edge functions import `_shared/language.ts` first so chat answers follow it. This way every screen is covered without wiring each component; add new English strings to the dictionary.
- Make each wall's layered picture from the hidden 3D room's guide render and the person's own preview (`wallScenes/`); each alternative is tone-matched and cut to its own shape from the photograph, and alternatives come only from the person's shop picks or moodboard palette. Build layers the Generator PRO way (`wallScenes/proLayers.ts`): an empty-room background, every piece as a shadow image (black on the piece, its cast shadow grey; multiply) plus the piece on black (lighten), Generator PRO's own composite model — keep it; a piece's cast shadow ignores the other pieces and the empty room's overall brightness; a piece that can't be outlined sends the whole wall to the cut-outs (never a gap); the viewer draws every wall on one canvas once its pictures are loaded, leaving out any picture that fails, walls and floor as see-through layers cut from the empty room; every outline comes from segmentation of the photo itself (`segment-photo`), never from the 3D guide; the old cut-outs are only a fallback. A wall colour is never made by the image AI: `wallScenes/wallPaint.ts` repaints the wall's own pixels on the picture (found by hue and smooth neighbour steps), keeping its light, in both pipelines; it must keep working with no edge-function redeploy. "Confirm options" flattens the choices into `showroom.final[wall]`, shown instead of the outline.
- Compose wall pictures from the database: the canvas comes from `showroom_canvas_presets` (closest shape, one scale per wall), each piece's drawing order, cut padding and hotspot from `showroom_item_specs` (one per `furniture_specs` box, added by trigger), and every made wall is stored in `wall_compositions` and `wall_composition_items`; keep the defaults in `wallScenes/composition.ts` in step with the seed.
- Draw the 3D showroom only from journey state (moodboard palette, preview read-out, room size, placements, chosen layout, kept pieces, wall items) through `showroom3d/model.ts`; never hard-code a room, piece or colour in the scene, and add no piece the person does not have.
- The app also runs from a sub-path (GitHub Pages at `/home-mockup/`): load public files through `asset()` from `src/lib/asset.ts` and build in-app links from `import.meta.env.BASE_URL`, never a path starting with "/".
- Choose AI models in `supabase/functions/_shared/aiModels.ts` only: each function maps its model ids to a job there with `useModels`, and calls go straight to Google or OpenAI when GEMINI_API_KEY or OPENAI_API_KEY is set, then through the Lovable gateway, and finally to the model the function names; pass GPT Image extras (mask, size, background) as the request's `hm` field.
